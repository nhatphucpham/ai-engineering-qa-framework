## Agent port, not prerecorded judgment

Two fresh runs execute the same frozen candidate independently. Each receives a new run/job/execution namespace, immutable input manifest and fresh collector observations. After cleanup, write a host-agent request containing selected criteria/policy, exact offered source/test artifact refs+hashes and per-test observations. Bind it by `jobDigest=SHA256(canonical finite JSON request)` plus run/job identity. The current host reasoning agent is invoked through an explicit request/response file port and must independently read each offered request. Record actual agent task/model/provenance; do not fabricate a provider invocation, token/cost data or unattended runtime connector. No old conclusion or prefilled binding is supplied. Host-mediated experiment is the only automation scope claimed.

The agent returns exactly one plan per selected AC, obligations/context and rationale, evidence reviews and mappings over offered IDs, all bound to the caller-held request digest/run identity. It does not author execution outcomes or acceptance of live credentials. Reject malformed/stale/cross-run proposals, nonoffered refs, source/evidence hash mismatch and unsupported positive claims. Source inspection is reasoning/context, never an execution record. Required observation levels are policy floors: AC-01 unit; AC-02/03/04 component integration. AC-04 specifically needs runtime observation of fixed-category API pagination/page-size behavior; source-only or service-only reasoning is insufficient for this selected claim. These are in-process fixture component levels, not HTTP/deployed integration.

Negative checks: wrong candidate/input digest, stale sibling host response and nonoffered evidence rejected; assertion fail versus error/skipped/missing remain distinct; duplicate execution/report IDs cannot overwrite evidence; provenance and humanDecision pending preserved. No auto source/test edits, approval, merge, retry, publication or report_ready.

## Core and viewer

Add a small adapter using existing `qa_core` contract/rules/internal report APIs without changing historical validators/schemas/goldens. Its report remains an **internal derived candidate** over this host-mediated assessment, not a durable accepted production run or ordinary export authorization. Caller holds input anchors; a package's self-hash is not source trust. Preserve failed plus incomplete/coverage gap semantics.

Generate a **narrow synthetic per-run view** from the two new reports: IDs/revision/scope, criterion status/reasons, actions/roles/doneWhen, and exact selected source/check excerpts with refs/hashes. Whitelist fields, escape all content, never expose the restricted whole-bundle publication package, credentials or arbitrary raw output/file access. The browser viewer is read-only and self-contained, generated after the actual runs; it must not pretend that an inline Start button calls a backend. Root verifies both runs in the real browser, including missing-evidence explanation and own-run evidence links. No auth/redaction/read-export/general AI quality claim from this toy view.
