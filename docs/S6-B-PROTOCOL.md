## Purpose / threat / acceptance trước code

Kiểm actual maintained Argon2id và PostgreSQL state cho dummy internal users, opaque sessions/refresh reuse, credential epochs, fixed project roles. Attacker input gồm sai/unknown/disabled credentials, expired/reused/forged/wrong-kind tokens, stale access/snapshot grant, client role/authority flags, cross-project IDs và concurrent privileged mutations. DB/process/key custody/transport được coi là trusted harness; không proof against DB administrator/host compromise. No HTTP/cookies/TLS/CSRF/OS credential store/SSO/service-worker identity/broker binding trong subset này.

- Local hash-pinned argon2-cffi25.1.0/bindings26.1.0/cffi2.1.1/pycparser3.12 trên Win64 Python3.14.8, origins/versions kiểm trước import; missing/mismatched/global fallback NOT READY. Argon2id RFC9106 low-memory profile64MiB/time3/parallelism4, salt16/hash32, actual5 trials + verification/rehash state, không production latency/settings decision.
- Private local bootstrap chỉ1 lần dưới DB guard, explicit caller-supplied dummy password, no default/backdoor reset. Admin-created/reset accounts phải change password trước privileged use. Only hashed passwords in DB; opaque access/refresh256-bit generated bằng `secrets`, separate prefixes/types, only SHA256 token digests persisted; never raw password/token/hash in evidence/logs.
- One DB admission mutex serializes account/session/role mutations for this fixture. DB clock controls expiry; authenticated transactions recheck live access with a final conditional DB mutation before commit. Delay-across-expiry rolls back all proposed state. Session/profile from DB, not client role/body. Fixtures access60s/refresh10min/family1h, login per-name/global windows are engineering bounds, not defaults/SLA.
- Untrusted requests enter **only explicit Identity.dispatch route whitelist**; raw store/bootstrap/token issuance/SQL helpers are trusted maintenance fixtures and cannot be selected by request operation. This is not a Python introspection/process sandbox or network deployment. All mutable identity state uses the same held mutex; final conditional checkpoint rechecks initially authenticated DB access/family expiry. An operation may intentionally invalidate its own session (logout/password change), so that own revocation does not undo a valid transaction; other actors cannot mutate credentials/roles while the mutex is held.
- Refresh atomically marks previous token used, increments family generation, issues new access/refresh, invalidates old access. Reuse of any used refresh **revokes entire family**, including current generation; concurrent same-token requests indistinguishable from replay: one may receive pair, then the loser revokes it. No grace window/idempotent retry promise; never retry refresh automatically after uncertain response. Unknown/expired/disabled/reset failure gives fixed generic E_AUTH.
- Logout revokes its family; credential reset/change/disable/admin privilege change increments account epoch and revokes all families. Login throttling records failure/admission even when returning E_AUTH; generic messages only, **not timing indistinguishability proof**. Unknown account does Argon2 dummy verification on admitted attempts. No full abuse/IP/distributed-rate policy.
- Fixed roles Admin(global), Owner/Runner/Viewer(project). Only Admin assigns/transfers Owner or Admin; Owner only manages Runner/Viewer in own project, cannot demote/remove current Owner. Last enabled Admin cannot be demoted/disabled, including competing processes. Account enabled/admin/membership/project state always live DB; roles from request cannot increase authority.
- Server-persisted grant bound to user/project/credential epoch/actions records snapshot scope; effective action = grant ∩ current role/project policy. Promotion does not expand old grants; downgrade/revoke blocks next operation. Simple queued run resource stores initiator from authenticated principal; Runner cancel own only, Owner/Admin any permitted project, Viewer no start/cancel. This is role/CAS persistence probe, not worker lifecycle/API integration. No raw-secret reveal/human auto-approval action for any role.
