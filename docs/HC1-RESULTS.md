## What changed

HC1 implements a versioned dispatch/completion boundary around the unchanged VF1 executor and core. Offers contain the exact offered job, bound native-response schema and instructions, with caller-held dispatch digest, deadline and native launch metadata. Completion archives the unchanged native proposal, validates execution/source/response bindings and automatically publishes core output and a standalone narrow dashboard together. Status/approval is never authored in the UI. There is no separate manual report derivation or viewer-build step.

Missing connector explicitly waits without a report. Callable conformance reserves a fresh dispatch once and never re-invokes an existing/uncertain attempt; transport exceptions retain waiting state. Deadline and cancellation fence publication; cancellation does not claim to terminate an in-flight native model. Exclusive local writer lock and accepted-directory publication serialize mutation; exact duplicate completion validates all derived bytes and deterministic receipt metadata. This is trusted-local coordination, not authenticated worker/remote broker, durable model exactly-once execution or S4-F machine-crash recovery.

Native invocation, saving the proposal and calling completion are **still mediated by the session tools**. A production unattended connector remains unavailable because its platform/adapter target has not been selected. No SDK/transport/production stack, real account/API/key/project, new packages, pilot/publish or Git action is implied. Scripted historical replay in tests is transport conformance only; it is not counted as live reasoning.
