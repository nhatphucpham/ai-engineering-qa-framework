## Ownership and one-use ordering

The ordinary UI client is a distinct real process: start through TLS, then exit. A separately monitored driver process owns the work and keeps service credentials off argv/URLs, receiving them over a private pipe. Scheduler/worker/collector audiences remain separate, each project-scoped. The driver claims and consumes the application's one-use effect admission through TLS. A fresh S4-F original unit initializes its private fixed engine, but cannot create a QA/probe container until the server-held context and consumed journal are durably associated with the exact current application assignment and effect nonce.

A private operator controller, absent from public operation routes, records the actual unit/context/boot/inodes/image and journal pins in `rt_runs.effect_witness`. It checks current worker/delegation/lease/run budget before any fire operation, using the existing identity DB mutex through engine IO and final clock checks. The same trusted local creator/observer facility as existing `observe_executor` supplies these observations; a worker's request booleans do not establish them. Bound resource identity retains its original project/run/assignment/attempt/fence/generation and effect nonce. S4-F's internal recovery job can use the exact effect nonce, while the separate original application admissionJobId is retained; neither identity silently replaces the other.

## Loss, cleanup and collector acceptance

Driver polling verifies public worker authority and bounded time. Client exit never cancels. On user cancellation, credential/config/delegation loss, real lease/run-budget expiry or whole-original-unit exit, it stops new effects and fences processing under the application mutex. Persist the original binding and resource history; advance application authority without rewriting original resource fields. A recovery epoch distinct from the original resource fence binds the S4-F private journal. A newer assignment/fence, unknown server head or external-authority mismatch blocks cleanup acknowledgement and replay.

After actual original unit/process quiescence, a genuinely new unit attaches the original private context. The independently CLEAN S4-F helper can perform its narrowly pinned dead-runtime-anchor repair, full enumeration and immutable inspection under both locks, followed by exact cleanup only. Capture its actual proof bytes and original/new process identities. Hold the latest application authority through IO and storage of the observation; loss or rollback of that acknowledgement leaves an incident, never assumed success. An explicitly recorded separate safety teardown may remove only independently owned original resources without acknowledging application cleanup or retiring newer authority.

The controller records an immutable cleanup-only observation with raw proof ref, canonical original admission/profile context ref, observed current application binding, and exact cleanup/resource fields. It must validate proof/context/binding/epoch/digests against independently held server anchors before writing. These are not a VF1 execution result or native offered QA job; preserve that distinction in their bytes/provenance. Only then does the independently enrolled collector submit the exact recorded pair through TLS. The run is already non-progressing, so existing cleanup-only acceptance keeps work_accepted=false and terminalizes cancelled/failed only after that independent proof. No accepted assessment/report/report_ready may follow. Worker, collector with no held observation, altered proof/resource fields, old fence and wrong project are denied.

Already collected successful work may also lose authority while awaiting assessment. A continuously monitored private reconciliation operation may fence and fail that processing only after confirming the original independently accepted exact cleanup proof is already durable. A successful collection is not permission to revive a lease or publish after expiry. Missing proof leaves the incident unresolved. No model outcome is invented to finish the run.
