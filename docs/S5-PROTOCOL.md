# S5 protocol v1 — offline GitHub normalization

Status: IN PROGRESS, 2026-11-12. Baseline 32bd110; S4-C changes preserved. Scope is P3-B S5 prerequisite for P4-D, not an authenticated adapter or integration gate. Pure synthetic recorded provider-shaped observations; no network, credentials, DB, run creation or persistence. Offline in-memory tests cannot prove atomicity, durable backlog, authorization, delivery verification, cursor safety or rate/history availability.

GitHub [webhook documentation](https://docs.github.com/en/webhooks/webhook-events-and-payloads) describes `X-GitHub-Delivery` as a delivery/event GUID; it is not a common timeline ID. [Issue event types](https://docs.github.com/en/rest/using-the-rest-api/issue-event-types#ready_for_review) describe ready_for_review ID and say `commit_id` is a commit referencing the issue, not the event head. [Timeline endpoint](https://docs.github.com/en/rest/issues/timeline#list-timeline-events-for-an-issue) paginates; [pull list](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests) is current pull state. Current SHA, timestamps and delivery IDs cannot establish the missing link. Provider-shape snippets are authored synthetic, not captured GitHub responses.

Normalizer receives webhook or timeline observations and returns explicit unresolved; a separate test-only trusted correlation assertion supplies occurrence and event revision to exercise the downstream invariant, **not evidence GitHub supplies that correlation**. No heuristic links allowed. Project/repo/PR scope is explicit. A bound occurrence can map to one revision; contradiction quarantines it and retains any prior binding/intent, never creates a second intent. Isolation and dedup are in-memory only. History-gap inputs explicitly remain unresolved.

Acceptance: duplicate webhook/poll observation cannot create duplicate intent; second ready occurrence at same SHA stays distinct; delayed webhook and changed head cannot assign current SHA; history gaps stay unresolved; conflicting SHA quarantines without another intent; fan-out yields independent per-project state. Reject malformed scope, IDs, SHA and unsupported actions safely. Harness must assert expected outcomes, run offline under Python 3.10+, and record source/fixture hashes before and after plus test results in fresh evidence. Independent review and successful checks required before any DONE claim. Live correlation method and authenticated/rate/history adapter gate remain open.

S5-RV-01: both webhook PR numbers must independently be positive integers (booleans and floats rejected) before equality. Project/delivery tokens are 1–128 ASCII characters: initial alphanumeric then alphanumeric, dot, underscore, colon or hyphen. These are spike input restrictions, not GitHub's complete identifier specification.
