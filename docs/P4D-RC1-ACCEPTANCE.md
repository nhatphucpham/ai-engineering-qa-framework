# P4D-RC1 acceptance — design versus execution

24/11/2026. Normative companion to [protocol 1.0.0](P4D-RC1-PROTOCOL.md). **All RC1 runtime cases below are NOT RUN.** This session delivers design and static checks only. Older HC1/M50/G1 PASS counts are historical evidence of their own contracts, not these cases. [Machine matrix](p4d-rc1-design/acceptance.json) preserves one status per case/port.

## Oracles and future evidence

Future offline tests must load authored provider-specific bytes into **separate** local/OpenAI/Anthropic encoders/mappers. Shared canonical/context validators are allowed. Author a new permitted synthetic corpus per protocol §5; preserve its exact projected/registered bundle and all lineage. Existing fixture_import restricted host-request/execution records are negative inputs, not positive reasoning-release permission. No fake reasoning or new check execution is claimed. A mutation must change one held field/condition so the negative distinguishes a bypass, not just mirror a helper's return value.

For each O case and each applicable port, retain raw fixture SHA256, profile/source versions, held offer/context/policy/budget, injected fault/clock, actual normalized result, release/invocation counts, reservation before/after and local ledger history. No credentials or raw project/prompt material in ordinary logs. For all negatives no candidate becomes accepted, all application dispatch/assessment/report/event counters are zero. A pure projection failure may have received one synthetic fixture response; no second invocation is permitted. Every port needs its own evidence; cannot multiply one result by three.

## Actual application integration is a separate gate

All I cases require a separately reviewed, versioned reasoning authority extension described in protocol §5, a new exclusive PostgreSQL schema, root-only serialized resource control after marker/path/status/input/budget preflight, and exact source pins before=after. No I case is runnable against unmodified API1.1. Use a newly registered **imported** synthetic job/execution/proposal corpus; label imported throughout. Existing actual QA/native campaigns are not rerun or relabeled. If later fresh actual execution is required, give it its own protocol and evidence.

Integration DONE needs all I cases plus each port's O evidence, latest-source independent CLEAN and actual final DB STOPPED. Each provider fixture integration proves **offline authored mapping through the application** only. Full P4-D stays OPEN for unimplemented integrated adapters and unresolved GitHub/provider capabilities; exact closure must reconcile the existing plan's offline conformance gate and explicit-gap allowance. Authenticated/network readiness, real provider/host controls and actual calls require a separately authorized environment; RC1 does not add real calls, platform choice or credentials as a mandatory synthetic-repo gate. No percentage change follows from any single case/slice.
