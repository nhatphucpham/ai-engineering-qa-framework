## Contract iap-b-1.0.0

- `AdminServices.dispatch`: exact route/version/fields, live user access + Admin mới create/rotate/revoke service. Opaque `s.<256-bit random>` credential trả riêng ở enrollment/rotation, only SHA256 digest persisted; no user role impersonation. Kind cố định scheduler/worker; audience `iap-scheduler`/`iap-worker`, project ceiling immutable. Owner/Runner/Viewer không enroll; no public bootstrap/SQL/helper/TTL override. Rotate/revoke tăng service epoch, old tokens không revive; revoke không tự enable lại.
- `ServiceAuthority.dispatch`: exact fields cho assign/check/renew/retire, chỉ credential `s.` đúng role audience, enabled/current epoch/DB expiry/project ceiling. User access/refresh không dùng làm service token; service token không dùng ở user/application routes. Caller không tự khai audience/role/authorized/cleanup. Envelope dùng exact version, IDs và strict integers (no bool/float); safe fixed codes, no credential interpolation.
- `assign` scheduler gọi với project/run/worker/expectedAttempt/ttl; server resolve immutable app run/delegation/grant, account enabled/must-change/credentialEpoch, current role/start permission, current project/policy epoch/config/actions và grant/delegation expiry. Không cần user session còn sống sau start commit. Service của scheduler/worker phải enabled/same enrolled epoch/project scope, credential chưa hết hạn. Worker không tự chọn run bằng check ID/hash rồi được quyền.
- Reservation lưu assignment ID server-generated, exact project/run/attempt/fence, scheduler+worker IDs/epochs, expiry bounded bởi delegation/grant/worker credential; mutable head chỉ current attempt/fence. Unique active head dưới common DB transaction. Two contenders cùng expectedAttempt chỉ1 winner; no duplicate authority row. Renewal chỉ current exact worker/assignment/attempt/fence trước expiry, không hồi sinh expired token/assignment hoặc tăng scope.
- `check`/`renew` xác thực **live** run delegation và both service epochs, exact assignment/head. User family logout/access expiry chỉ dừng interactive; reset/change/disable/admin-change credential epoch, role downgrade/remove, project/policy/grant revoke/expiry chặn metadata operation tiếp theo. Policy update của IAP-A luôn tăng epoch nên old run delegation không được tự bind grant mới. No general membership epoch/anti-rollback provider; live role restoration chỉ được xét trong persisted original ceiling, không claim missed revocation history.
- `retire` scheduler đúng current project/assignment/attempt/fence fence reservation, không cần run delegation còn allow start vì đây là reducing-authority operation. Retired/expired assignment không renew/check. New attempt chỉ sau metadata retirement và fresh live checks; **không** cấp quyền retry actual workload khi chưa cleanup. Scheduler revoke còn để pending metadata reservation, operator/cleanup workflow thực chưa có.
- Tất cả mutation/checks+safe audit dùng common held identity mutex. Final conditional DB checkpoint rechecks service credential + grant/delegation/assignment deadlines; expiry qua thời gian sau tentative writes rollback unit. Revoke/rotation/policy/user mutations dùng cùng mutex; không check-then-write transaction riêng hoặc trust synthetic bool. Denial audit sau rollback riêng, unavailable fail closed; commit error → fixed E_DEPENDENCY, no partial assignment/head/audit. No exactly-once external effect/release guarantee.
