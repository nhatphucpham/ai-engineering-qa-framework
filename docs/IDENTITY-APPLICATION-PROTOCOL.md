## 4. Identity, snapshot grants và live state

### 4.1 Các identity và versions tách biệt

Logical records mới phải có explicit version và strict fields trước implementation; bảng này **chưa là wire schema/P1 change**.

| Record | Server-owned binding tối thiểu | Ý nghĩa |
|---|---|---|
| InteractivePrincipal | kind=user, userId, session/familyId, credentialEpoch, access/family expiry | Xác thực lại mỗi request; role/membership không lấy từ token body/client |
| ServicePrincipal | kind=service, serviceId, enrollmentEpoch, enabled, audience, capabilities/project assignments, credential expiry | Namespace và verifier riêng; user access/refresh/grant không được dùng làm service credential và ngược lại |
| SnapshotGrant | grantId/version, subject kind/id, credential/enrollment epoch, project, allowed actions/resource bounds, immutable config/policy versions, expiry/revoked | Persisted ceiling, không tự là bearer capability; bắt buộc authenticated subject match và live checks |
| RunDelegation | runId, initiator hoặc subscription principal, originating grant, project/candidate/config/data-policy/input anchors, action/check/outbound ceilings, credential/enrollment epoch, expiry/revoked | Quyền background có nguồn, không lưu user token cho worker; không tự lấy từ runId/package |
| AttemptAssignment | project/run/attempt, worker serviceId/enrollmentEpoch, lease/fence/stateVersion, expiry, config/image/check scope | Mỗi claim/renew/result/broker use gắn exact attempt; expiry theo trusted server clock |
| LivePolicyFence | project enabled + policyEpoch, account/membership/delegation versions, service epoch, secret head version/epoch nếu dùng | Trusted provider giữ latest monotonic epochs; missing/unavailable/rollback-unknown → deny/block, không lấy max từ untrusted input |

Các epoch ở đây có namespace riêng, không so `credentialEpoch == secretEpoch` hoặc đồng nhất các projects ở spike schemas. Policy/config update/revoke phải tăng fence tương ứng atomically và invalidate stale dispatch permits/cache. Không giảm/reuse epoch khi enable lại hoặc restore. Snapshot policy/config vẫn immutable; live state chỉ **thu hẹp** authority, không viết lại historical inputs.

Effective authority là intersection của authenticated identity hiện tại, snapshot grant/delegation ceiling, live fixed role/membership/project/policy, exact resource/attempt, budgets và content classification. Promotion/config widening không mở rộng run/grant cũ; cần grant/snapshot/run mới có lineage. Downgrade/remove/disable/revoke chặn operation tiếp theo dù snapshot cũ từng cho phép. Secret version rotation không âm thầm thay credential trong attempt đã đóng băng; cần explicit newly authorized binding hoặc new run, giữ provenance.

### 4.2 Session lifetime khác background run authority — design mới

Start cần user session hợp lệ tại mutation. Sau start đã commit, worker dùng service identity + RunDelegation, không impersonate user hay tái sử dụng user token. Đóng desktop, access expiry hoặc logout family chỉ dừng interactive requests; **không tự cancel run** đã được giao. Background vẫn phải kiểm live initiator enabled, credential epoch, project/membership/delegation/policy trước mỗi side effect. Reset/change password/disable/admin-change tăng credential epoch trong S6-B nên delegation cũ bị fence; explicit grant/delegation revoke cũng vậy. Không tự reissue để sống lại sau login/reset/re-enable.

Đây là lựa chọn contract để đáp ứng worker chạy khi desktop đóng, **chưa implementation**; S6-B `check` vẫn đòi live user access, không được gọi với access giả cho background. Family replay revokes cả family, có thể vô hiệu pair vừa trả; interactive phải reauthenticate, không auto-retry refresh. Nếu successful refresh mất response, chỉ riêng response loss không tự revoke family; client không biết pair mới nên không retry used token và phải reauthenticate. Family revoke không bằng credential-epoch revoke; run không dựa vào family còn sống. Event-trigger run dùng configured service/subscription delegation và owner-approved frozen ceilings; chưa có ingress implementation, không dựng human initiator từ event payload.

## 5. Atomic live checks và external release

### 5.1 Application mutation boundary

Không dùng `Identity.dispatch('check', …)` rồi `S2.complete(…)` như proof atomic auth. Kết quả check chỉ là observation tại transaction cũ. Trước code integration cần transaction-aware trusted policy provider + mutation unit chung, không ghép các DB namespaces của spikes bằng bool `policy_ok`.

1. Parse bounded request/allowlist; authenticate đúng principal kind/audience. Resolve project/resource từ trusted registry, đối chiếu với request scope trước đọc bytes. Unknown/cross-project references trả cùng safe denial, không tiết lộ object tồn tại.
2. Trong một authoritative transaction/unit: lock hoặc CAS các auth/account/membership/project/policy/delegation fences, idempotency receipt và run/attempt liên quan theo lock order cố định; mọi writer sửa quyền phải dùng cùng protocol. Read live authority + immutable ceilings + expected state/version/anchors; trusted clock kiểm expiry **tại conditional write**, không chỉ SELECT ban đầu.
3. Commit mutation + audit + durable command receipt + required outbox intent atomically. Expiry/version/policy race/commit failure rollback toàn unit; không response accepted/event/content ref trước commit. Own logout/password-change được phép tự revoke như S6-B, không là ngoại lệ chung cho application write.
4. Unique idempotency identity gồm **principal kind/id + project + operation + client idempotency key**; canonical payload digest là immutable comparison field của receipt, **không nằm trong unique key**. Atomically insert-or-compare trong cùng transaction: same identity/same digest trả stable committed receipt chỉ sau current read authorization; same identity/khác digest → conflict, không tạo run/receipt thứ hai. Uncertain commit: query receipt qua authenticated boundary, không retry external effect mù. Retry DB bounded, không đổi request snapshot/epoch để lách denial.

Tại docs slice chưa chọn storage/transaction primitive hoặc runtime. Integration gate cần chứng minh common fencing authority thực thi; nếu auth state/provider nằm khác DB, check-then-write/TTL cache không đủ. Chưa có chứng minh distributed protocol tương đương thì dependent mutation **blocked**, không claim atomicity.

### 5.2 External side effect và revocation cutover

Network/container IO không nằm trong DB transaction dài. Durable intent chưa cho phép execution. Dispatcher/broker phải lấy **one-use release permit** từ cùng trusted live fence authority ngay trước launch/send/release chunk; permit bind exact operation/resource/attempt/epochs/expiry/budget và sink, không gửi raw capability cho workload.

Release admission và revoke phải có ordering chung: revoke commit trước admission → không phát bytes/launch; admission trước revoke → effect có thể đã bắt đầu, đánh dấu in-flight/uncertain và yêu cầu stop/cleanup, không hứa thu hồi byte đã gửi. Không được có khoảng check → queue → gửi không recheck. Một permit được consume chỉ một dispatch; dispatcher identity và channel phải bind permit tới sink. Actual transport/gateway cancellation và revocation delivery chưa có; TTL đơn lẻ hoặc synthetic cleanup bool không chứng minh invariant này.

IO timeout/crash sau permit consumption: ghi outcome unknown, reconcile bằng operation ID/provider receipt nếu có; không phát lại automatically. Retry chỉ bằng explicit bounded policy, new live checks/permit và evidence idempotency của sink; không hứa exactly-once. Revoke/lease loss → ngừng permit mới/renew/acceptance, fence attempt, durable stop request. Cancelled chỉ sau exact authenticated cleanup proof; timeout failed `cleanup_unconfirmed` + open incident, không retry/claim mới trong khi cleanup chưa giải quyết. Completion và cancel/revoke tranh cùng fence; chỉ một terminal winner. Completed trước revoke giữ lịch sử immutable nhưng mọi read/export sau đó vẫn kiểm live quyền.

Reads/streams cũng là release: resolve classified immutable view, current auth/policy trước response và mỗi bounded chunk/event batch; stream có authorization deadline, revoke ngừng batches tiếp theo. Replay cursor chỉ vị trí, không là quyền; resume/reconnect reauthenticate/recheck project + object + current fence. Không public pre-signed content URL sống vượt revoke; phần đã giao không thể thu hồi.

## 7. Scoped secret broker proposal — không phải Vault facade

Broker authenticate service/assignment rồi resolve secret ref từ trusted run config; không nhận keys, raw secret, URL, env-name/path/command tùy ý từ user/model/worker. Request logical binding: operation ID, service/audience, project/run/attempt/fence, check ID hoặc provider adapter ID, purpose, exact secret ref/version/epoch, approved sink ID, input-context manifest digest và policy fence. Fields chỉ là selectors/expected values, phải đối chiếu server registry; secret anchor không lấy từ envelope tự khai.

Effective use cần đồng thời service capability, run delegation ceiling, live initiator/project/policy, secret enabled/current expected head, allowed purpose/check/provider, budget và **sink binding**. Hai allowed operations ban đầu: broker-owned outbound provider request, hoặc broker-owned injection vào exact isolated check sink đã chứng minh S4 controls. Broker không trả plaintext cho caller/supervisor/model, không cấp reusable secret handle/bearer URL hoặc broad environment. Provider auth chỉ nằm trên approved channel, không đi vào model context. Container injection chỉ là design option, chưa ready: workload có thể đọc credential nên phải kiểm egress/collector/taint actual trước enable.

No user-controlled endpoint/redirect/proxy/DNS route; gateway kiểm đích thực qua channel lifecycle, deny redirect sang sink khác. Local connector cũng chịu outbound/data lineage policy, không host-process bypass. Cho phép provider không đồng nghĩa cho phép gửi source/summary bị cấm: input manifest phải có trusted origin/classification/derived-from graph; deny/restricted source truyền taint qua derived report/summary/tool output. Unknown lineage → block outbound; client sanitizer/redaction labels không đủ. No output content echo qua broker status/error/telemetry.

Private encrypted store chỉ được gọi bởi trusted broker-owned adapter sau live checks, không expose `exercise_private_open`, `envelope`, `rewrap`, bootstrap/SQL qua request. S6-A helper hiện trả bytes cho operator và không authenticate broker: cần adapter mới và authenticated sink, không rename helper thành broker. Key custody/nonce history/read-only restore rules vẫn giữ; restore chỉ metadata/key backup không tái cấp use authority. Mất trustworthy latest policy/nonce anchors → remain blocked/read-only, không tự enable workers/write/use.

Cleanup sau cancel/revoke/expiry phải retire injection/sink, stop container/descendants/network access và reconcile scoped outputs. Observation phải do trusted collector/supervisor có service identity, exact cleanup request + assignment/run/attempt/original fence + image/container/sink IDs + observed terminal/resource state + timestamp/verifier basis. Worker `clean=true` không proof. Collector checks no-follow/size/time/type và secret/denied-source taint; raw logs encrypted quarantine, chỉ trusted sanitized projection đã có provenance mới xem xét ordinary release. Hiện chưa có collector/sanitizer; zeroization hoặc arbitrary hostile repo isolation chưa được chứng minh.

## 8. Safe error/audit/retry contract

Error vocabulary là logical mới, **không đồng nhất codes các spike**: `auth_required` (invalid/old/expired/reset/disabled session, generic), `denied` (scope/role/grant/audience/cross-project, không existence oracle), `stale_context` (authorized caller có stale CAS/epoch, phải refresh/re-authorize chứ không nâng quyền), `restricted_content`, `dependency_unavailable`, `invalid_input`, `outcome_unknown`. Không trả raw exception/body/path/SQL/token/hash/password/secret; internal safe reason codes phân biệt auth/policy/lease/dependency cho người vận hành đã authorized. Refresh replay giữ E_AUTH semantics cũ và reauthenticate.

Accepted mutation audit trong cùng transaction: correlation/operation ID, principal kind + server ID, delegation/grant refs, scoped resource IDs, snapshot versions/digests và live fence IDs, attempt/fence, allow/deny reason code, receipt/outbox/cleanup refs. Denial được ghi bằng safe independent audit unit, không khiến denied mutation commit; audit sink không sẵn thì side effect fail closed, không silent allow. Failed command audit không phát report_ready. External dispatch ghi intent/permit consumption, observed outcome hoặc unknown, reconcile/stop/cleanup history append-only. Không ghi raw credentials, access/refresh digests, content hoặc provider exception. Evidence cho canary scan dùng match flags/hash-of-safe-fixture files, không đưa dummy secret vào Git.

## 9. Acceptance/failure protocol cho harness kế tiếp

**Tất cả IAP-A01…A24 dưới đây: NOT RUN integration.** Chúng là test obligations cho implementation sau, không phải execution results phiên này. Một bool/dict giả lập chỉ kiểm logic shape, không đóng DB race/authenticated worker/engine/network gate.
