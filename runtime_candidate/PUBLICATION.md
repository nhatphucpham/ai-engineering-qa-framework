# M50 private byte storage and report projection

Trusted bootstrap creates an absolute, new directory under an existing private service-owned parent using `BlobStore.create(path, owner=owner)`. The owner is a stable operator-held identifier. Later processes use `BlobStore(path, owner=owner)`. The marker binds format, owner, normalized path and filesystem directory identity. The same open store object rejects a replacement directory. Keep the store inaccessible to ordinary clients and other OS writers. The marker and content hashes provide integrity checks, not OS authentication or key custody.

`put(raw)` returns `{"sha256": "...", "byteLength": n}` after writing and flushing the bytes, publishing exclusively under the digest, and reading back the exact contents. Objects are limited to 8 MiB. An existing object with the same bytes succeeds. A different length, digest, corrupt object, link, wrong marker or missing object raises the fixed `E_INTEGRITY` code. `get(ref)` accepts only those two fields and verifies length and digest from file bytes at read time. An application client never supplies a file path.

Windows operations pin each directory component against renaming and open reparse points themselves for rejection. The file read handle excludes writers, and same-volume create-only publication uses a write-through rename. The Linux implementation uses directory file descriptors, no-follow opens, fsync and `renameat2(RENAME_NOREPLACE)`. Local NTFS is exercised by the Windows checks. Other filesystems, OS power loss and deployment recovery require separate qualification. The code never enumerates or recursively removes staged files. A killed writer can leave a private `.stage-…` file, which cannot be addressed through `get`. A crash after rename can leave a complete unreferenced object. Only a committed authorized DB reference makes a report visible. A restore into a fresh directory needs a fresh marker and independently checked object copies.

## Publication and source references

Call `prepare(bundle, assessment, expected_bundle_digest=…, expected_assessment_digest=…, run_id=…, report_id=…)` with the accepted issuer-held digests and IDs. Each input is finite canonical JSON of at most 1 MiB. The unchanged core stages and rechecks the exact package against those caller-held anchors. The input assessment is a supplied judgment. An imported specimen or scripted proposal carries no claim of a fresh model call.

The returned `PreparedPublication` has these fields.

| Field | Intended use |
|---|---|
| `package`, `private_bytes`, `private_ref` | Restricted whole-input replay. The canonical bytes include all embedded projects, private text, staged graph and raw inputs. Only the trusted service uses these values. |
| `view`, `view_bytes`, `view_ref` | Target-only ordinary report. The canonical bytes contain issuer-bound run/report IDs, core status and coverage, core reason codes and actions, proposed owner roles, effective constraints, pending human decision and legacy projection status. |
| `lineage` | Private maps under `criteria`, `constraints` and `evidence`, from the per-report generated IDs to original source IDs. Use them only inside the server when joining independently registered and currently authorized project/task/revision records. |

The ordinary representation follows an explicit field allowlist. An evidence reference such as `evidence-1` names only a row scoped to the selected project and handoff, cited by a target criterion. Its metadata includes typed level, outcome, provenance kind and whether its revision matches the candidate. A separate array preserves contextual evidence. Criteria and constraints also use local ordinals. Roles outside the bounded routing vocabulary become `requirement-owner`. No paths, actor names, rationales, locators, raw source bodies, other projects or user-provided identifiers are copied into the report beyond the two issuer-bound IDs. Action descriptions and completion conditions come from the checked core's generated action templates. This is field selection and typing, not text scanning or sanitization.

The application checks the live run/project/grant/lease and compares package target bindings with the trusted run. It stages exact private and view bytes and verifies their descriptors before its atomic report/completion/outbox transaction. Reading a report, exporting source bytes or joining richer source metadata requires the application's current authorization and data policy. A package's self-digest, derived evidence alias or synthetic classification grants no authority. No code in these modules accesses a database, starts workers or chooses a model.

From the repo root, run `py -3 -B -m unittest runtime_candidate.test_publication -v`. Coverage includes four competing independent writers, killing a writer after a partial write, reference/marker and existing-byte tampering, namespace replacement, wrong anchors, consistent input substitution, package graph tampering, a secret canary inside schema-valid IDs, a foreign project and mixed failure with an evidence gap. Full milestone acceptance still requires integrated authenticated clients, real transaction and crash/restart/restore checks and independent review.
