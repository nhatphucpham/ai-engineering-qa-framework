# Candidate application API 1.1.0

This is the M50 synthetic reference application contract, not a production stack choice. Canonical inputs and API JSON are finite UTF-8. API version is `m50-application-1.1.0`; POST body `version` must match and is removed before the operation's exact fields below. No unspecified fields. No principal, role, outcomes, policy labels or SQL supplied by a request are trusted. Sessions use user access Bearer, service routes enrolled service Bearer of the stated audience, never interchangeable. Dummy bootstrap is an operator-only Python API, absent from HTTP allowlist. Version1.1 adds explicit fenced no-effect claim recovery; it does not reinterpret the preserved1.0 integration records or perform automatic migration of their disposable schemas.

TLS loopback supports POST `/v1/<operation>` and GET `/v1/events?project=<id>&run=<id>&after=<n>`. Body limit1MiB; bounded ordinary content release64KiB; SSE at most64 records per reconnect. No redirects/auth forwarding. Every ordinary read and each released SSE event rechecks current session, project role/data policy and any held grant immediately at release; generation is not release authorization. Partial bytes already sent cannot be recalled. Event cursors are exact project/run scoped and carry no authority; gaps/ahead cursor return `E_RESYNC_REQUIRED`, and `run_read` provides a consistent sequence watermark. Imports/execution/raw inference/accepted assessment are separately labeled.

Each request factory returns `dispatch(operation,token,body)->dict`, `close()`, and **`release_unit(operation,token,body,result)` returning a context manager**. For session_read/project_list/project_read/run_list/run_read/events/report_read/source_read/report_export, transport enters a fresh release unit before headers and around every write of at most4096bytes, including each SSE record boundary; all body bytes combined are bounded64KiB. The unit reauthenticates and holds the live-policy/identity DB mutex through the actual bounded write. Thus a revoke committed before admission denies the next chunk; an already admitted chunk may finish before revoke can commit. Recheck without holding ordering through IO is insufficient. A missing hook fails closed before any successful response. On denial/error after headers, close the connection without appending a second JSON response; client treats truncation as incomplete. This interface is internal, never a public route or caller-supplied context manager.

User authorization failure is generic `E_DENIED`403 whether the supplied project/run/ref exists or not; transport404 is only an unknown route, never a resource existence probe. Claim response has exactly `runId,project,assignment,fence,lease_token,leaseExpiresAt,snapshotId,candidateDigest,inputDigest,configVersion,policyVersion`; these are assigned-worker scoped values. Scheduler passes this grant to the assigned worker through its registered channel; it never shares its scheduler credential. Any consumer with a user/scheduler/wrong-worker token is denied by audience and row binding.

## Exact operation shapes

Every POST includes `version`. Field lists below exclude that common field. All responses are JSON objects; successful command acceptance has `accepted=true`, `state`, `runId`, `stateVersion` and HTTP202 for run_start/run_cancel/worker_admit. Other successful operations HTTP200. Fixed errors are `E_INPUT`, `E_VERSION`, `E_AUTH`, `E_DENIED`, `E_CONFLICT`, `E_STALE`, `E_BUDGET`, `E_UNRESOLVED`, `E_RESYNC_REQUIRED`, `E_INTEGRITY`, `E_DEPENDENCY`; no path/raw payload/password/token/traceback is returned in errors. HTTP mappings are400,426,401,403,409,409,429,409,409,409,503 respectively. Unknown route404 and unsupported method405 are transport diagnostics. IDs and exact refs are values, never file paths.

## Trusted records and effect/assessment admission

Operator setup registers source bytes and their exact revision, SHA256, length, classification and lineage from approved synthetic fixture paths only. Repo/task and handoff registrations have different adapter kinds; HTTP intake cannot assert classification, pass outcomes or accepted authority. Imported evidence remains imported and is not relabeled as executed evidence. Raw/secret/tainted records are restricted for all QA roles, including Admin; untrusted `redacted`/`safe` flags never override registry classification.

Collector and assessor have separate enrolled credentials, independent of the submitting worker. A worker cannot call either audience. Collector input references bind one consumed server effect nonce, original assignment/fence/run/candidate/check-registry IDs and full resource identity. Server revalidates the offered frozen source hashes and structured observation IDs/outcomes against the immutable collected record before accepting an assessment. Assessor submits an assessment candidate, but current service authority+scope, expected server bundle/observation manifests and core's strict schema/policy are checked before it becomes accepted. Server never learns its expected input identity or cleanup proof solely from a package/worker's self-hash/boolean.

Actual check collection/witness provenance must come from the separately controlled rootless executor/collector process. Operator-only fixtures may register imported corpus inputs for persistence regression; those tests are labeled imported and cannot close executed-worker acceptance. P4-C additionally needs actual whole-supervisor/pre-identity recovery evidence in its own versioned protocol and independent review. No golden assessment/report is preaccepted at bootstrap to claim end-to-end reasoning. A fresh host assessor may be mediated while P4-D remains open, and absent assessment leaves waiting rather than fabricated reasoning.

Restore is maintenance-only. Server opens safe/read-only until schema marker, current external authority/config head pins and all referenced blob bytes/lengths match a separately held trusted checkpoint; archive metadata cannot declare itself latest. Actual backup/restore/restart and failed stale/missing anchors are required before the selected milestone is complete. Full P3-B/P5 deployment/key-custody readiness remains separate; this contract does not close those gates.

Claim response loss is an uncertain *delivery*, not permission to repeat execution. Retrying worker_claim may report E_STALE after its durable CAS; the same scheduler explicitly calls worker_recover_claim using its original request context. It returns either the one current fenced grant, or terminal no-effect failure, never the plaintext prior lease (only its digest was persisted). If original admission wins before recovery, recovery returns E_UNRESOLVED and the original effect must be observed/reconciled. If recovery wins, old worker admission is fenced. Recovery without current original scheduler/worker authority never discloses a lease. Delivery exhaustion returns E_BUDGET; routine cancel can close a proved no-effect assignment, while admitted/uncertain effects remain subject to exact cleanup.
